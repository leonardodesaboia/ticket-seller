Documentação dos módulos

Cada módulo relevante deve possuir um arquivo Markdown neste diretório.

Exemplos:

identity.md
organizations.md
events.md
inventory.md
orders.md
payments.md
tickets.md
checkin.md
finance.md
Conteúdo mínimo

A documentação do módulo deve conter:

responsabilidade;
limites;
entidades;
casos de uso;
invariantes;
estados;
eventos;
portas;
dependências permitidas;
dependências proibidas;
riscos;
testes obrigatórios.
Regra

Não repetir a documentação global.

O arquivo do módulo deve conter somente informações específicas da capacidade de negócio.
